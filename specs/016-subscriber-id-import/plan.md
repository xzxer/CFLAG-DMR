# Implementation Plan: F14 — Subscriber ID Import

**Branch**: `016-operational-features` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)

## Summary

Build a local RadioID.net subscriber database with smart auto-update support. Core components: two migrations (`subscriber_ids` table + system_settings keys), `app/subscribers/manager.php` with conditional-GET import logic and minimum-interval enforcement, last-heard integration, admin override management, and a cron-compatible CLI script. The admin page surfaces import status, next-allowed-import time, and cron setup instructions.

**Key finding from research**: The correct CSV URL is `https://radioid.net/static/user.csv` (singular). The file is 15.9 MB, ~306k records, updated daily at ~05:00 UTC. It supports conditional GET via `Last-Modified` / `If-Modified-Since` — daily cron runs will usually get a 304 response and skip the import entirely.

## Technical Context

**Language/Version**: PHP 8.3, strict types  
**Primary Dependencies**: PDO (MariaDB), PHP `fopen()` HTTP stream wrapper for CSV download  
**Storage**: MariaDB — new `subscriber_ids` table, 4 new `system_settings` keys  
**External Service**: `https://radioid.net/static/user.csv` — publicly accessible, ~15.9 MB, daily updates  
**Performance Goals**: Full import < 3 minutes; conditional-GET "no-change" check < 2 seconds  
**Constraints**: Minimum 23-hour re-import interval enforced in code; `User-Agent` header required by RadioID.net API policy; no user input in HTTP requests  
**Scale/Scope**: 306k rows, bulk upsert in 500-row batches, indexed by `radio_id`

## Implementation Phases

### Phase 1: Migrations
- `021_create_subscriber_ids.sql` — CREATE TABLE subscriber_ids
- `022_subscriber_import_settings.sql` — INSERT system_settings keys

### Phase 2: Manager — import core
- Create `app/subscribers/manager.php` with `import_subscribers_from_radioid(bool $force = false): array`
- Implement minimum-interval check (reads `subscriber_min_import_interval_hours` + `subscriber_last_import_at`)
- Implement conditional GET: build stream context with `If-Modified-Since` header and `User-Agent`
- Implement fgetcsv row loop with 500-row batch upserts (source='local' rows protected)
- Capture new `Last-Modified` from `$http_response_header` after 200 response
- Update all four system_settings keys on successful import

### Phase 3: CLI script
- Create `scripts/import_subscribers.php` — bootstraps the app and calls `import_subscribers_from_radioid()`
- Log result to stdout in one-line format: `[2026-05-27 06:00:01] status=ok imported=306412 batches_failed=0`
- Exit 0 on success/not_modified/too_soon; exit 1 on error

### Phase 4: Lookup functions
- Add `get_subscriber_import_stats()`, `get_subscriber()`, `get_subscribers_for_ids()` to manager.php
- Add `upsert_subscriber_override()`, `delete_subscriber_override()`, `get_subscriber_overrides()` to manager.php

### Phase 5: Admin UI
- `public/admin/subscribers/index.php` — import stats panel, "Import Now" + "Check for Updates" buttons, cron setup instructions, override management table

### Phase 6: Last-heard integration
- Update admin and user-facing last-heard pages to call `get_subscribers_for_ids()` for batch callsign display

### Phase 7: Validation
- Run a full import and confirm 300k+ rows in `subscriber_ids`
- Run "Check for Updates" within 23h of previous import; confirm "too soon" response
- Manually set `subscriber_last_modified` to a past date; confirm conditional GET triggers a re-import
- Create a local override; run full import; confirm override survives

## Open Questions

- Should the cron setup instructions on the admin UI show the actual server path? Yes — `__DIR__`-based path displayed dynamically.
- Should "Import Now" bypass the minimum interval? Yes — it is an explicit admin override (passes `force=true`). "Check for Updates" respects the interval.
- What if `allow_url_fopen` is disabled in php.ini? Detect on page load and show a warning on the admin page. The CLI script should also check and exit with a clear error.
