# Implementation Plan: F5 — Hotspot & Repeater Registration

**Branch**: `007-hotspot-registration` | **Date**: 2026-05-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/007-hotspot-registration/spec.md`

## Summary

Registered, email-verified users can add hotspot/repeater devices, which enter a pending approval queue. System admins approve or deny registrations. Approved devices are collected into a whitelist-eligible DMR ID set consumed by config generation (F7). US4 (talkgroup subscriptions) is gated on F6 and deferred; the DB schema is defined now.

## Technical Context

**Language/Version**: PHP 8.3 — `declare(strict_types=1)` in all source files

**Primary Dependencies**: PDO/MariaDB (existing), `app/auth/` (existing roles/session), `app/database/` (existing connection)

**Storage**: MariaDB — `devices` table (migration 008); `device_talkgroup_subscriptions` deferred to migration 009 after F6's talkgroup table exists

**Testing**: Manual verification per quickstart.md — no automated tests

**Target Platform**: Apache/PHP on Ubuntu 24.04; `public/` is document root

**Project Type**: Web application (server-side rendered PHP)

**Performance Goals**: Standard — page load under 2s; device list scoped to current user so no pagination needed for MVP

**Constraints**: CSRF on all POST forms; `htmlspecialchars` on all rendered user input; PDO prepared statements only; no secrets in code

**Scale/Scope**: Small network, O(100s) of devices total; no pagination required for device list

## Implementation Details

### Migration 008: `migrations/008_create_devices.sql`

```sql
-- Migration 008: Create devices table
-- Part of F5: Hotspot & Repeater Registration

CREATE TABLE devices (
    id            INT UNSIGNED  NOT NULL AUTO_INCREMENT,
    user_id       INT UNSIGNED  NOT NULL,
    callsign      VARCHAR(16)   NOT NULL,
    dmr_id        INT UNSIGNED  NOT NULL,
    device_type   ENUM('hotspot','repeater') NOT NULL,
    hardware_desc VARCHAR(255)  NOT NULL DEFAULT '',
    status        ENUM('pending','approved','denied') NOT NULL DEFAULT 'pending',
    approved_by   INT UNSIGNED  NULL,
    denied_reason TEXT          NULL,
    reviewed_at   DATETIME      NULL,
    created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP
                                         ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_user_id (user_id),
    KEY idx_status  (status),
    KEY idx_dmr_id  (dmr_id),
    CONSTRAINT fk_devices_user     FOREIGN KEY (user_id)     REFERENCES users (id) ON DELETE CASCADE,
    CONSTRAINT fk_devices_approver FOREIGN KEY (approved_by) REFERENCES users (id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### Service Layer: `app/devices/manager.php`

```php
declare(strict_types=1);
require_once __DIR__ . '/../database/connection.php';

// Validation
function validate_dmr_id(string $raw): int|false
// ctype_digit() check; cast to int; range 1000000–9999999; return int or false

function validate_callsign(string $raw): string|false
// trim; length 3–16; preg_match('/^[A-Z0-9\/]+$/i'); return trimmed or false

// Read
function get_user_devices(int $user_id): array
// SELECT all devices WHERE user_id = ? ORDER BY created_at DESC

function get_device(int $device_id, int $user_id): array|null
// SELECT one device WHERE id = ? AND user_id = ? (ownership check baked in)

function get_pending_devices(): array
// SELECT devices JOIN users WHERE status='pending' ORDER BY created_at ASC
// Returns array with user display_name, callsign, email for admin view

function get_whitelist_eligible_dmr_ids(): array
// SELECT d.dmr_id FROM devices d
// JOIN users u ON u.id = d.user_id
// WHERE d.status = 'approved' AND u.moderation_state = 'active'
// Returns flat array of DMR ID strings

// Write
function register_device(int $user_id, array $data): array
// ['ok' => bool, 'error' => string|null, 'device_id' => int|null]
// Checks: user active; DMR ID valid; DMR ID not already pending/approved
// by another user; inserts with status='pending'

function update_device_hardware(int $device_id, int $user_id, string $hardware_desc): bool
// UPDATE devices SET hardware_desc = ? WHERE id = ? AND user_id = ?

function delete_device(int $device_id, int $user_id): bool
// DELETE FROM devices WHERE id = ? AND user_id = ?

function approve_device(int $device_id, int $admin_id): array
// ['ok' => bool, 'error' => string|null]
// Check: no other status='approved' device with same dmr_id for active user
// UPDATE devices SET status='approved', approved_by=?, reviewed_at=NOW()

function deny_device(int $device_id, int $admin_id, string $reason): bool
// UPDATE devices SET status='denied', approved_by=?, denied_reason=?, reviewed_at=NOW()
```

### User Page: `public/user/devices.php`

```
require_once app/auth/roles.php
require_once app/devices/manager.php
start_session()
require_login()
$user = current_user()
if ($user['moderation_state'] is suspended/banned) → redirect with error

Handle POST actions:
  action=register  → validate → register_device() → redirect
  action=delete    → delete_device() → redirect
  action=edit_hw   → update_device_hardware() → redirect

$devices = get_user_devices($user_id)

Render HTML:
  - Page title "My Devices — CFLAG DMR"
  - Link rel stylesheet /assets/css/app.css
  - Section: "My Devices" heading
  - Table: Callsign | DMR ID | Type | Status | Hardware | Date | Actions

    - Actions: Edit (inline form for hardware_desc), Delete (confirm)
  - Section: "Register a Device" form
    - Fields: Callsign (text), DMR ID (text), Type (select), Hardware (text)
    - CSRF token hidden field
    - Submit button "Register Device"
  - Nav: ← Home or ← Dashboard
```
