# Implementation Plan: F16 — Backup & Rollback

**Branch**: `016-operational-features` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)

## Summary

Surface `config_generation_history` in the admin UI with a paginated history page, per-row download and rollback actions, and a running config viewer. Rollback re-uses F13's apply pipeline by refactoring `apply_hblink_config()` into a `apply_hblink_config_text()` function that accepts any config_text. Adds migration 023 (`rolled_back_from_id` FK on the history table) to mark rollback records.

**Dependency**: F13 (Controlled Restart) must be implemented first — migration 023 extends migration 020, and `apply_hblink_config_text()` is a refactor of `apply_hblink_config()`.

## Technical Context

**Language/Version**: PHP 8.3, strict types  
**Primary Dependencies**: PDO (MariaDB), same file system paths as F13  
**Storage**: MariaDB — `config_generation_history` extended with `rolled_back_from_id`  
**Target Platform**: Linux server (Apache/www-data), same as F13  
**Performance Goals**: History page loads in under 1s (no config_text in list query); rollback completes in under 30s  
**Constraints**: `config_text` must not be selected in list queries; download streams directly from DB, no temp files  
**Scale/Scope**: Low-frequency admin action; history table may have hundreds of rows over months

## Implementation Phases

### Phase 1: Migration
- `migrations/023_add_rolled_back_from_id.sql` — add `rolled_back_from_id` column + FK constraint

### Phase 2: PHP layer refactor and additions
- Refactor `apply_hblink_config()` → `apply_hblink_config_text(string $config_text, int $actor_id, ?int $rolled_back_from_id)` in `app/config/generator.php`
- Update `apply_hblink_config()` to generate config_text then call `apply_hblink_config_text()`
- Add `rollback_to_generation(int $generation_id, int $actor_id): array`
- Add `get_config_generation_by_id(int $id): array|null`
- Add `get_running_hblink_config(): string|null`
- Update `get_config_generation_history()` to accept `$offset` param and include `rolled_back_from_id`

### Phase 3: Admin history page
- `public/admin/config/history.php`:
  - List view: paginated table, metadata columns only, action buttons per row
  - Download action: stream config_text with Content-Disposition header
  - Rollback action: POST handler → `rollback_to_generation()` → PRG flash
  - Running config action: `get_running_hblink_config()` → display in modal/pre block
  - Diff expand: inline AJAX-free toggle using `<details>` or hidden div + JS show/hide
- Update `public/admin/config/index.php` to add "View History" link

### Phase 4: Validation
- Manual test: roll back to a previous generation, verify new history record has `rolled_back_from_id` set
- Manual test: download a history record, verify the `.cfg` file matches expected content
- Manual test: "Show Running Config" shows the current `/etc/hblink3/hblink.cfg` content
- Verify `config_text` is never selected in the list query (EXPLAIN or log check)

## Open Questions

- Should diff expand be an inline toggle (no page reload) or a separate detail page? Inline toggle (`<details>` element) is simpler — avoids a round-trip for what may be a small diff.
- Running config modal vs inline display? A modal keeps the history table visible for reference — prefer modal with close button.
