# Implementation Plan: F3 — User Registration & Accounts

**Branch**: `004-user-registration` | **Date**: 2026-05-25 | **Spec**: [spec.md](spec.md)

---

## Summary

Adds public self-registration for licensed amateur radio operators. A visitor submits their callsign, DMR ID, email, password, and display name. The server validates the fields, optionally verifies the callsign/DMR ID pair against RadioID.net, creates the account, and logs a single-use verification token. The account is not accessible until the token link is visited. Three new public pages (`/register.php`, `/verify-email.php`, `/resend-verification.php`) plus updates to `/login.php` and the admin user management pages.

---

## Technical Context

**Language/Version**: PHP 8.x — `declare(strict_types=1)` on all files.

**Primary Dependencies**: PDO (MariaDB), cURL (RadioID.net API, built-in), PHP `mail()` (placeholder, dev mode writes to log file).

**Storage**: MariaDB — two new tables (`email_verifications`, `system_settings`), one altered table (`users` adds `callsign` and `email_verified_at`).

**Testing**: Manual — 13 quickstart scenarios in `quickstart.md`.

**Target Platform**: Apache 2.4 on Linux. `public/` is document root.

**Project Type**: Web application — server-rendered PHP pages.

**Performance Goals**: Registration form submission including RadioID.net lookup ≤ 8 seconds (5s cURL timeout + 3s server overhead budget).

**Constraints**: No Composer. No framework. cURL only for external HTTP. All output `htmlspecialchars`-escaped. All SQL via PDO prepared statements.

### Step 2: Foundation (parallel)

All can be written and tested independently after Step 1:

**`app/email/mailer.php`**:
```php
function send_verification_email(string $to_email, string $display_name, string $token): void
```
- Reads `env('EMAIL_DEV_MODE')`. If `'true'`: write line to `/var/log/cflag-dmr-email-dev.log`.
- Format: `[timestamp] TO: {email} | LINK: http://{HTTP_HOST}/verify-email.php?token={token}`
- Otherwise: `mail($to_email, 'Verify your CFLAG DMR email', $body, "From: noreply@{$host}")`.

**`app/registration/register.php`**:

```php
function validate_registration(array $data): array  // returns ['field' => 'error message', ...]
function lookup_radioid(int $dmr_id): ?array         // returns ['callsign' => '...', 'id' => N] or null; throws \RuntimeException on API error
function is_radioid_validation_enabled(): bool
function register_user(array $data): int             // INSERT users, returns user_id
function create_verification_token(int $user_id): string  // INSERT email_verifications, returns token
```

`validate_registration()` checks:
- callsign: `/^[A-Z]{1,2}[0-9][A-Z]{1,3}$/i`, max 10 chars
- dmr_id: `ctype_digit`, exactly 7 chars
- email: `filter_var($email, FILTER_VALIDATE_EMAIL)`
- password: `strlen >= 12`
- display_name: `strlen >= 2 && strlen <= 64`
- Uniqueness: single query `SELECT 1 FROM users WHERE username = ? OR email = ? OR callsign = ? OR dmr_id = ? LIMIT 1`; on match return generic "already in use" on the conflicting field. (To avoid revealing which field, return the same error text on all three uniqueness fields.)

`lookup_radioid()` cURL flow:
```
GET https://www.radioid.net/api/dmr/user/?id={dmr_id}
CURLOPT_TIMEOUT = 5
On HTTP 200 + results[0]: return ['callsign' => results[0]['callsign'], ...]
On HTTP 200 + empty results: return null (not found)
On timeout/error: throw \RuntimeException('RadioID.net lookup failed')
```

**`app/auth/login.php`** (update):
```php
const LOGIN_OK         = 'ok';
const LOGIN_INVALID    = 'invalid';
const LOGIN_UNVERIFIED = 'unverified';

function attempt_login(string $identifier, string $password): string
```
- Detect email vs username by `str_contains($identifier, '@')`.
- Query: `SELECT id, username, display_name, password_hash, moderation_state, email_verified_at FROM users WHERE (username = ? OR email = ?) LIMIT 1` — pass identifier twice.
- After `password_verify` passes: check `email_verified_at IS NULL` → return `LOGIN_UNVERIFIED`.
- `suspended`/`banned` → return `LOGIN_INVALID` (unchanged behaviour).
- Success → set session, update `last_login_at` → return `LOGIN_OK`.

### Step 3: Public Pages (parallel after Step 2)

**`public/register.php`**:
- `GET`: render form (flash old input values if redirected back).
- `POST`: verify CSRF → `validate_registration()` → if RadioID.net enabled: `lookup_radioid()` → if errors: re-render with errors → `register_user()` → `create_verification_token()` → `send_verification_email()` → PRG redirect to `?success=1`.
- `GET ?success=1`: render confirmation page.
- If already logged in: redirect to `/admin/`.

**`public/verify-email.php`**:
- Read `$_GET['token']`.
- `SELECT * FROM email_verifications WHERE token = ? LIMIT 1`.
- Not found: render "invalid link" page.
- Already used (`used_at IS NOT NULL`): render "already verified" page.
- Expired (`expires_at < NOW()`): render "expired" page with resend link.
- Valid: `UPDATE users SET email_verified_at = NOW() WHERE id = ?`; `UPDATE email_verifications SET used_at = NOW() WHERE id = ?`; redirect to `/login.php?verified=1`.

**`public/resend-verification.php`**:
- `GET`: render form.
- `POST`: verify CSRF → check rate limit (MAX created_at query) → if rate limited: show same success message, do nothing → look up user by email (unverified) → invalidate old tokens → create new token → `send_verification_email()` → show success message.

**`public/login.php`** (update):
- Update label from "Username" to "Username or Email".
- Change `attempt_login($_POST['username'], $_POST['password'])` call to capture string result.
- On `LOGIN_UNVERIFIED`: show specific message + resend link.
- On `LOGIN_INVALID`: show generic error (unchanged).
- On `LOGIN_OK`: redirect (unchanged).
- Handle `?verified=1` GET param: show "Email verified! You can now log in." flash.

### Step 4: Admin Pages (parallel after Step 2)

**`public/admin/users/index.php`** (update):
- Add `?verified=0` filter: append `AND u.email_verified_at IS NULL` to query when `$_GET['verified'] === '0'`.
- Add "Unverified" badge (new CSS class `.badge-unverified`) and display it when `email_verified_at IS NULL`.

**`public/admin/users/view.php`** (update):

- If `email_verified_at IS NULL` and viewer has `system_admin` role:
  - "Manually verify" button (POST action=`manual_verify`).
  - "Resend verification email" button (POST action=`resend_verify`).
  - "Delete account" button (POST action=`delete_user`, btn-danger, requires confirmation via JS `confirm()`).

  - `resend_verify`: invalidate old tokens; create new token; `send_verification_email()`; `log_audit_action()`.
  - `delete_user`: `DELETE FROM users WHERE id = ? AND id != ?` (prevent self-delete); log; redirect to `/admin/users/`.

## Security Checklist

- [ ] CSRF token on all POST forms (`register.php`, `verify-email.php` N/A GET, `resend-verification.php`, `view.php` new actions)
- [ ] All `$_GET`/`$_POST` values that reach HTML escaped with `htmlspecialchars(ENT_QUOTES, 'UTF-8')`
- [ ] All SQL via PDO prepared statements — no string interpolation
- [ ] `attempt_login()` always calls `password_verify()` before checking `email_verified_at` (prevents timing oracle)
- [ ] Resend endpoint never reveals whether email is registered
- [ ] Uniqueness errors use generic "already in use" — do not name which field conflicts
- [ ] `lookup_radioid()` rejects non-2xx responses and treats timeout as "unavailable" (not rejection)
- [ ] Dev email log file not inside `public/` (in `/var/log/`)
- [ ] `delete_user` action prevents self-deletion
- [ ] Token comparison uses direct string equality (no `==` type coercion risk; both are strings from DB)
