# Implementation Plan: F13 — Controlled Restart / Reload

**Branch**: `016-operational-features` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)

## Summary

Fix the broken F7 apply/restart workflow by implementing a safe, audited config application pipeline: generate → validate → backup → atomic write → docker restart → status poll → audit record. Adds a migration extending `config_generation_history`, new PHP functions in `app/config/generator.php`, and updates the admin Network Config page to surface the Apply button and HBLink status indicator.

## Technical Context

**Language/Version**: PHP 8.3, strict types  
**Primary Dependencies**: PDO (MariaDB), `shell_exec()` for docker commands  
**Storage**: MariaDB — `config_generation_history` extended, `audit_log` writes  
**Target Platform**: Linux server (Apache/www-data)  
**Project Type**: Web admin interface  
**Performance Goals**: Apply completes in under 30 seconds end-to-end  
**Constraints**: No user input touches shell commands; hardcoded paths only; www-data needs Docker/sudo access  
**Scale/Scope**: Single admin action; low frequency (a few times per week at most)

## Implementation Phases

### Phase 1: Server permission setup (manual/deployment step)
- Add www-data sudoers rule for docker restart
- Create `/etc/hblink3/backups/` directory, owned by www-data
- Verify www-data can write to `/etc/hblink3/`

### Phase 2: Migration
- `migrations/020_extend_config_generation_history.sql` — add applied, applied_at, apply_success, apply_error, backup_path columns

### Phase 3: PHP apply pipeline
- Add constants for paths to `app/config/generator.php`
- Implement `apply_hblink_config(int $actor_id): array`
- Implement `get_hblink_status(): string`
- Extend `get_config_generation_history()` to include apply columns

### Phase 4: Admin UI
- `public/admin/config/index.php` — add HBLink status chip, "Apply & Restart" button with confirmation, apply result flash message, diff preview section
- `public/admin/config/history.php` — add applied/success columns to the history table, error message on hover/expand

### Phase 5: Validation
- Manual end-to-end test on dev server with actual HBLink container
- Verify backup files are created before each apply
- Verify failed validation doesn't touch the live config
